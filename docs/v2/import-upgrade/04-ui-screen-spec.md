# I1 — מפרט מסכים

המוקאפים הם כיוון חזותי. הכללים העסקיים גוברים עליהם כשיש סתירה. אין לבנות את המסכים בשלב I1.

השפה נשארת עברית וכיוון RTL. הטיפוגרפיה היא Heebo. הצבעים נשארים שפת העיצוב הקיימת של Mlaiko: ירוק פעולה, כרטיסים לבנים, גבול אפור בהיר, אזהרה כתומה. אין מיתוג חדש ואין כיתוב V2 ללקוח.

שלושת המסכים חייבים לעבוד בדסקטופ, בטאבלט ובמובייל. במובייל טבלאות הופכות לכרטיסי שורה. כפתור הפעולה הראשי נשאר גלוי בלי לגלול מעבר לקיפול הראשון כשאפשר.

הקבצים:

- `mockups/01-import-center.jpg`
- `mockups/02-import-order-detail.jpg`
- `mockups/03-goods-receiving.jpg`

הם הועתקו מצרופות השיחה. לפני כן התיקייה לא הייתה בריפו.

## מסך א׳ — מרכז היבוא

מקור חזותי: לוח עם כפתור "הזמנה חדשה", חמישה מדדים, חיפוש, מסנני סטטוס ספק ותקופה, וכרטיס לכל הזמנה.

כל כרטיס מציג נתונים שמורים:

- מספר הזמנה
- ספק, וסוג יצרן או סוחר
- כמות צמיגים שהוזמנה
- ערך ההזמנה במטבע ההזמנה
- התקדמות תשלום: סכום ששולם מול סכום שסוכם, לא אחוז שנגזר משם הסטטוס
- מצב המשלוח העדכני מאירוע הלוגיסטיקה האחרון
- תאריך הגעה צפוי ותאריך הגעה בפועל כשהוא קיים
- כמות שהתקבלה וכמות שנותרה
- התראה שמקורה בנתונים: איחור מול תאריך צפוי, חוסר, מסמך חסר שסומן, או יתרת תשלום
- פעולה הבאה שהשרת מתיר

חיפוש לפי מספר, ספק וטקסט. סינון לפי ספק, סטטוס מסחרי, סטטוס לוגיסטי, טווח תאריכים ומספר הזמנה.

מדדים:

- הזמנות פעילות
- כמות שהוזמנה בהזמנות הפעילות
- שווי ההזמנות הפעילות במטבעות שלהן, בלי להמיר אוטומטית כשאין שער
- סכום ששולם לספקים
- משלוחים שתאריך ההגעה הצפוי שלהם בתוך שבעה ימים

סתירה מול המוקאפ: אחוזי 62, 55 ו־60 על ציר המשלוח נראים כמיקום בסרגל סטטוסים. אין להציג אותם. במקומם מוצגת אבן הדרך האחרונה שנשמרה, ותאריכי היעד והביצוע שלה. אחוז תשלום מותר רק כחלוקה של סכום ששולם בסכום שסוכם.

"התחלת קליטה" על הכרטיס מוצג רק כשהשרת מסמן שהמשלוח הגיע למחסן. סטטוס שנבחר ידנית במסך אינו מספיק.

הזמנות רכש מקומיות אינן מופיעות במרכז היבוא. הן נשארות במסך הרכש, ונקלטות אחר כך באותו מסך קליטה.

## מסך ב׳ — פרטי הזמנת יבוא

עמוד קבוע `/import/:id`, לא מודאל של כל התהליך. המוקאפ מציג כותרת, ציר שלבים, כרטיסי סטטוס, תשלום, עלויות ופרטי הזמנה, ואז לשוניות.

לשוניות:

1. סקירה
2. מוצרים
3. תשלומי ספק
4. שילוח
5. הוצאות יבוא
6. מסמכים
7. קליטות
8. היסטוריה

הציר מציג גם אבני דרך עתידיות, במצב "טרם התרחש", בלי תאריך בדוי. תאריך בפועל מופיע רק מאירוע שנשמר.

הפעולה הראשית לפי מצב השרת:

| מצב | פעולה |
|---|---|
| טיוטה מסחרית | עריכה או אישור הזמנה |
| אושרה, הספק מכין | עדכון הכנה |
| יצאה לדרך או בים | עדכון משלוח |
| בנמל או במכס | עדכון מכס |
| הגיעה למחסן | התחלת קליטה |
| נקלטה חלקית | המשך קליטה |
| נסגרה | היסטוריה ועלות סופית, בלי עריכת תנאים |

כפתור "קליטת סחורה" במוקאפ נעול עד שהמחסן אושר. טקסט העזרה נשאר: הקליטה נפתחת אחרי הגעה למחסן.

כרטיס התשלום מציג את מטבע ההזמנה. כרטיס ההוצאות מציג שקלים ואת הסכום במטבע המקור כשהוא שונה. אין לחבר אותם ליתרה אחת בלי לתייג את המטבע.

טבלת המוצרים במוקאפ מציגה מק״ט, מידה, כמות, מחיר ספק, עלות נחיתה ומחיר מכירה. עמודות העלות והמחיר נשארות "לא ידוע" כשאין חישוב שמור. אין להציג 0 במקום ערך חסר.

## מסך ג׳ — קליטת סחורה

מסך משותף לרכש מקומי וליבוא. הכותרת מציגה את המסמך המקור: מספר יבוא או מספר הזמנת רכש, ספק, מצב המשלוח ותאריך ההגעה.

לכל שורה:

- שם, מותג, מידה ומק״ט
- כמות שהוזמנה
- כמות שהתקבלה קודם, בנפרד לתקינים, לפגומים ולחסרים
- יתרה פתוחה
- כמות תקינה בקליטה הזו
- כמות פגומה או בהסגר
- כמות חסרה או במחלוקת
- הערה
- מסמכים מצורפים לקליטה

המוקאפ של 1,000 יחידות, 980 תקינים, 8 פגומים ו־12 חסרים מקיים:

```
980 + 8 + 12 = 1,000
```

המסך חוסם שמירה כשהסכום חורג מהיתרה או כשאותה יחידה נספרת בשני טורים.

"שמירת טיוטה" שומרת את הטופס בלבד. "אישור קליטה" שולח ל־RPC האטומי. אחרי הצלחה הכפתור ננעל לאותו מפתח. כישלון משאיר את המספרים על המסך.

המוקאפ מתאר יצירת תנועות מלאי, עדכון עלות וממוצע נחיתה. הטקסט הזה מתאר את היעד. כל עוד המנוע המשותף כבוי, המסך החדש אינו מוצג כפעולה חיה, ומסך הקליטה הישן נשאר המסלול הפעיל של היבוא.

במובייל כל שורת צמיג היא כרטיס עם שלושת שדות הכמות, לא טבלה חתוכה.
